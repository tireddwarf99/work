# Развёртывание облака (этап 3)

Документ — инструкция по развёртыванию и источник истины по конфигурации.
Фактические проверки: см. журнал диагностики приложения (экран
«Діагностика») и отчёты этапов; дата последней проверки указывается в
отчёте, не в этом файле.

## Текущая конфигурация

- Проект: `dwarfs-life-app`, регион Firestore: `europe-central2`.
- База: **`(default)`** — именно она используется приложением (REST-адрес
  `databases/(default)`). Если в проекте есть другие базы (например,
  созданная вручную `dwarfsdatabase`) — приложение их не трогает.
- Правила: файл `firestore.rules` в корне репозитория, **UID владельца уже
  вшит** в файл (`2fANEOpUDmczCaVAhb6FF36iBL93`). Плейсхолдера
  `OWNER_UID_PLACEHOLDER` больше нет.
- OAuth: Android-клиент (авто, привязан к SHA-1 debug-ключа), Web-клиент
  (serverClientId для Credential Manager), Desktop-клиент (PKCE + loopback
  `127.0.0.1`). Desktop-клиент требует client secret при обмене кода —
  значение зашито в `firebase_config.dart` и не является конфиденциальным
  (см. §9: installed-app клиент публичный). При желании проверь в Google
  Cloud → Credentials, что тип клиента — «Desktop app».

## Если нужно сменить владельца

1. Новый владелец входит в приложении → его UID виден в Настройках и в
   Діагностиці (`auth: signedIn uid=...`).
2. Открой `firestore.rules`, замени UID в строке
   `request.auth.uid == '...'` на новый.
3. Firebase Console → Firestore → база `(default)` → вкладка **Rules** →
   вставь содержимое файла → **Publish**.
4. Правила применяются в течение 1–2 минут.

Правила проверяют не только UID, но и форму данных: entity-документ обязан
содержать ровно набор полей протокола (type/revision/base_revision/
commit_seq/modified_at/deleted/device_id/payload/last_op_id) с
неотрицательными целыми ревизиями, workspace — только счётчик и epoch.
Это защита от случайного повреждения модифицированным клиентом; при
изменении протокола обновляй и `firestore.rules`, и функции `validEntity`
/ `validWorkspace` синхронно.

Важно: проверка `request.auth.uid == uid` (workspace) и жёсткая сверка с
владельцем — это два барьера; второй гарантирует, что даже случайно
созданный workspace другого пользователя не получит доступ.

## Диагностика проблем синхронизации

Настройки → **Діагностика**: состояние (`auth:`, `sync:`), журнал событий,
кнопки «Sync now», «Об'єднати з хмарою» (первый вход), «Прийняти новий
знімок» (появляется только при смене epoch сервером и требует явного
подтверждения — несинхронизированные локальные изменения будут потеряны).

Типовые сообщения:

| Сообщение | Причина | Действие |
|---|---|---|
| `404 database does not exist` | База `(default)` не создана | Создать базу по ссылке из ошибки |
| `PERMISSION_DENIED` | Правила не опубликованы / чужой UID | Проверить Rules на `(default)` и UID |
| `workspace belongs to another account` | Локальные данные другого аккаунта | Выйти (с удалением копии) и войти заново |

## Структура данных в Firestore

```
workspaces/{uid}                     — active_epoch, commit_seq
workspaces/{uid}/epochs/{epoch}/entities/{entity_id}
    type          — int (индекс SyncEntityType)
    revision      — int
    base_revision — int
    commit_seq    — int
    modified_at   — ISO UTC
    deleted       — bool (компактный маркер без содержимого, §10)
    device_id     — string
    payload       — JSON-строка снапшота сущности
```

Смена epoch (§12) выполняется приложением только по явному подтверждению
пользователя; автоматическая смена без потери данных — этап 6 (режим
«Заменить»).

## Токены

Firebase refresh token хранится только в защищённом хранилище ОС
(Android: EncryptedSharedPreferences поверх Keystore через MethodChannel;
Windows: DPAPI через FFI, файлы в приватной области данных) — не в
ZIP-экспорте, не в логах (§9).

## Ограничения v1 (честно)

- Проверка nonce в desktop-входе не включает криптографическую валидацию
  подписи id_token по JWKS Google (TLS + state/nonce закрывают основные
  векторы; полная валидация — этап полировки).
- Background-синхронизация (WorkManager) и виджет — этап 5; сейчас
  синхронизация работает в открытом приложении и по кнопке.
